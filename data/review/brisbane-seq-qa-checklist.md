# Brisbane/SEQ Imported Water Data QA Checklist

Use this checklist to review records generated by the staging import preview before any status is promoted beyond `imported`.

## Preconditions
- [ ] Import preview was run and output exists at `data/staging/brisbane-seq-import.preview.json`.
- [ ] Reviewer confirms this workflow uses source-backed files only (no live scraping).
- [ ] Reviewer confirms all values under review are placeholder or source-verified values only.

## Review status lifecycle
Records must move through this lifecycle in order:

1. `sample`
2. `imported`
3. `reviewed`
4. `publishable`
5. `published`

### Status intent
- `sample`: placeholder-only rows shown in beta mode.
- `imported`: machine-imported rows pending human QA.
- `reviewed`: human verified against source metadata and value/unit checks.
- `publishable`: review-complete and eligible for publish approval.
- `published`: explicitly approved and released.

## Required gating rules
- Imported records must **not** become `reviewed` without human verification.
- Reviewed records must **not** become `publishable` without all required fields:
  - source URL
  - publication date
  - last checked date
  - value
  - unit
  - coverage level
  - confidence level
- Low confidence records cannot become `publishable` or `published`.
- Records with missing source URLs must remain `imported` or move to `rejected`.
- No records are automatically published.

## Human QA checklist
For each imported row:

- [ ] Verify suburb/postcode/coverage mapping is correct for Brisbane/SEQ scope.
- [ ] Verify parameter name matches intended measure from source.
- [ ] Verify source URL is reachable and matches source owner.
- [ ] Verify publication date from source.
- [ ] Verify last checked date is current and recorded.
- [ ] Verify value matches source exactly.
- [ ] Verify unit matches source exactly.
- [ ] Verify coverage level is appropriate.
- [ ] Verify confidence level is not low for publishable candidates.
- [ ] Record reviewer initials/name and review date.
- [ ] Add notes for anomalies, assumptions, or follow-up actions.

## Outputs
- Approved records go into `data/review/reviewed-records-template.csv`.
- Rejected rows and reasons go into `data/review/rejected-records-template.csv`.
- Source-level checks are captured in `data/review/source-verification-checklist.csv`.

## Example review outcome (placeholder Brisbane/SEQ data)
- Example: `Brisbane City` fluoride row imported with placeholder value is checked against a known source reference entry.
- If source URL/date/value/unit/coverage/confidence are all verified and confidence is not low, status can move `imported -> reviewed -> publishable`.
- Publishing still requires explicit manual approval; no auto-publish step is allowed.
